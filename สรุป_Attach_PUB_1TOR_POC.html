MFA / SSO implementation brief
เอกสาร: ผนวก 6 การทดสอบการใช้งานจริง | 5 หน้า | ประเมินแบบ “ผ่าน/ไม่ผ่าน”
ขอบเขตงานรอบนี้: ทำเฉพาะ 3 ส่วน
1) MFA กับ In-house Web Application ผ่าน OIDC และ API
2) MFA/SSO กับ In-house Web Application ผ่าน SAML
3) MFA กับ In-house Mobile Application ผ่าน OIDC

OneLogin เหมาะกับขอบเขตนี้ โดยใช้เป็น Identity Provider และ MFA Provider; รายการ AD, VPN, Adaptive Authentication และ Admin/RBAC ในเอกสารเป็นข้อมูลอ้างอิงของ TOR แต่ ไม่รวมในงานรอบนี้

สรุปย่อสำหรับการดำเนินงาน

งานนี้เป็นการทำ Proof of Concept เพื่อพิสูจน์ว่า OneLogin สามารถทำ MFA และ SSO ให้กับ Web Application และ Mobile Application ได้ ผ่านมาตรฐาน OIDC, SAML และ API

VPN Gatewayเชื่อมต่อด้วย SAML และส่ง Attribute เพื่อกำหนด Policy; Password + Push MFA + Number Matching; ลงทะเบียน Mobile authenticator ครั้งแรก

2. ประเมินความสอดคล้องกับ OneLogin

ข้อกำหนดผลประเมินหมายเหตุ
AD, OU, Sync แบบ real-timeรองรับOneLogin AD Connector เลือก OU ได้ และ sync ผู้ใช้/การเปลี่ยนแปลงจาก AD ได้
SAML SSO + Custom Attributeรองรับใช้ OneLogin เป็น IdP และกำหนด Attribute Statement/Mapping ให้ VPN หรือ Web App
OIDC Web + Mobileรองรับรองรับ OIDC; สำหรับ Mobile ควรใช้ Authorization Code + PKCE
Push MFA และ REST APIรองรับOneLogin Protect และ MFA API มีการ enroll, trigger push และ verify
Adaptive / Geo / TOR / riskมีความสามารถรองรับSmartFactor ระบุ network, geography, device และ time anomalies รวมถึง TOR เป็นสัญญาณความเสี่ยง
Number Matchingต้องยืนยันกับรุ่น/แผนบริการเอกสารทางการที่ตรวจพบยืนยัน Push แบบ Accept/Deny แต่ยังไม่พบหลักฐานชัดเจนสำหรับ Number Matching แบบพิมพ์/เลือกเลขตาม TOR
2 อุปกรณ์ + Primaryต้องทดสอบ PoCมี API/การจัดการ MFA device แต่เงื่อนไข Primary และพฤติกรรม Push เหมือนกันต้องตรวจใน tenant จริง
หน้าล็อกอินปรับ Logo/Background/Linkมีแนวโน้มรองรับต้องตรวจความสามารถปรับแต่งของแพ็กเกจ/tenant และสาธิตตามเกณฑ์
RBAC สำหรับผู้ดูแลรองรับโดยหลักจัด role/สิทธิ์แยกตามงานได้ แต่ต้อง map ชื่อ role ให้ตรงกับ TOR

3. ข้อสรุปสำหรับขอบเขตนี้

แนะนำให้ใช้ OneLogin ได้ โดยวาง OneLogin เป็น Cloud IdP/MFA แล้วเชื่อม Web Application ด้วย OIDC และ SAML ส่วน Mobile Application ใช้ OIDC + PKCE

จุดที่ต้องยืนยันก่อนสรุปผล POC: Number Matching, การบังคับ MFA ครั้งแรก, การส่ง Custom Attribute, REST API สำหรับ Push/TOTP และความสามารถปรับแต่งหน้า SSO Login

แผนทดสอบที่ควรทำ

  1. สร้าง Next.js Web Application สำหรับทดสอบ OIDC และ SAML
  2. สร้าง React Native Mobile Application สำหรับทดสอบ OIDC + PKCE
  3. ตั้งค่า OneLogin Application, Redirect URI, Client ID/Secret และ Claims/Attributes
  4. ทดสอบ Password + Push MFA, Number Matching, MFA Enrollment และ TOTP/Push API
  5. ทดสอบ Logo/Background/Hyperlink ของ SSO Login Page และจัดทำหลักฐานผ่าน/ไม่ผ่าน

4. สิ่งที่ต้องทำและ Stack / Tools เฉพาะงานรอบนี้

งานที่ต้องดำเนินการ

  1. Web OIDC/API: เชื่อม OIDC, ส่ง Custom Attribute, ทำ MFA และเรียก Push/TOTP ผ่าน REST API
  2. Web SAML: เชื่อม SAML SSO, ส่ง Custom Attribute, ทดสอบ Push MFA + Number Matching และปรับแต่งหน้า Login
  3. Mobile OIDC: พัฒนา React Native, ใช้ OIDC + PKCE และทดสอบ PIN/Biometrics + Push MFA

ส่วนสิ่งที่มีในโปรเจกต์
Web OIDCNext.js Authorization Code + PKCE, state/nonce, JWKS ID-token verification, session และ logout; ขอ scope openid / profile / email และแสดง Custom Claims employee_code (รหัสพนักงาน), department (แผนก) จาก ID token ที่ตรวจสอบแล้วใน Account บน dashboard โดยไม่ใส่ข้อมูลตัวอย่างแทนค่าที่หาย
Okta Authorization Policyเพิ่ม Access Policy เฉพาะแอป Web OIDC บน Authorization Server default เพื่อแก้ no_matching_policy; อนุญาตเฉพาะ authorization_code และ scopes openid / profile / email โดยคง Password + Okta Verify Push (2FA) ไว้ อ่านค่ากลับผ่าน API ยืนยันแล้ว; login ครบ flow ต้องทดสอบผ่านเบราว์เซอร์ ไม่เพิ่ม Stack / Tools
Web SAMLSP-initiated login, SAML metadata, ACS callback และอ่าน Attribute หลังตรวจผลยืนยันตัวตน; แสดงชื่อ อีเมล employee_code และ department ใน Account เช่นเดียวกับ OIDC รองรับ Attribute แบบ string หรือ array ค่าเดียว และ session เดิมที่เก็บ Attributes อยู่แล้ว โดย SAML ไม่ต้องขอ scope แบบ OIDC
Account menuเมนู Account มุมขวาบนทั้งหน้าแรกและ dashboard หลังเข้าสู่ระบบ แสดงชื่อ บัญชีผู้ใช้ อีเมล รหัสพนักงาน แผนก และ protocol พร้อมลิงก์ข้อมูลบัญชีและ Logout; แยกบัญชีผู้ใช้ OIDC preferred_username / SAML NameID ออกจากอีเมล ใช้ HTML details/summary ไม่เพิ่ม Stack / Tools
Logout กลับหน้าแรกOIDC ใช้ id_token_hint และ post_logout_redirect_uri; session SAML ใช้ Okta Org Sign-Out พร้อม fromURI กลับ http://localhost:3000 โดยเพิ่ม Trusted Origin สถานะ ACTIVE แบบ REDIRECT เท่านั้นแล้ว การตั้งค่านี้ไม่ใช่ SAML Single Logout protocol และไม่เพิ่ม Stack / Tools
หน้าแจ้งข้อผิดพลาดหน้า error ภาษาไทยโทนเขียวสำหรับ OIDC / SAML พร้อมคำแนะนำ ปุ่มลองใหม่ กลับหน้าแรก และรหัสอ้างอิง; รองรับ callback ไม่สมบูรณ์, session หมดอายุ, สิทธิ์ไม่ผ่าน, ตรวจผลยืนยันตัวตนไม่ผ่าน, หน้า 404 และข้อผิดพลาดระหว่างแสดงผล โดยใช้ Next.js / React / CSS เดิม ไม่เพิ่ม dependency
Okta APIServer-side routes สำหรับ configured factors, test user, enrolled factors, enroll, activate และ verify (TOTP/Push); API token ไม่ส่งไป client
Mobile OIDCExpo React Native, Code + PKCE, token validation API, Account, SecureStore, Biometrics/device unlock และ Logout; Metro export/TypeScript/Android debug APK ผ่านแล้ว ยังไม่รันบนอุปกรณ์จริง
Docker / DatabaseDocker Compose รัน Web แบบ dev local พร้อม hot reload และ PostgreSQL 16 container, persistent volume, healthcheck และ dependency ordering; มี Dockerfile สำหรับ production แยกไว้
เอกสาร/ทดสอบREADME.md, docs/TEST_PLAN.md และ scripts/verify-config.mjs

คำสั่งรัน Web: docker compose up -d แล้วเปิด http://localhost:3000 แก้ source แล้ว hot reload ได้ ไม่ต้อง build image ใหม่

ผลตรวจ error handling: ตรวจ HTTP บน local dev ผ่านทั้ง OIDC callback ที่ไม่สมบูรณ์, state หมดอายุ, provider error, SAML response ที่ไม่ถูกต้อง, การป้องกัน dashboard เมื่อไม่มี session, หน้า 404 และ redirect logout; การ login/logout ครบ flow กับบัญชีจริงต้องทดสอบในเบราว์เซอร์ที่มี Okta session

หน้าเดโมเฉพาะ Push / TOTP ไป Primary — TOR 3.5 / 3.6

Login แล้วเปิด Primary MFA Demo: เลือก Primary และยืนยันการจับคู่ TOTP ครั้งเดียว จากนั้นกดส่ง Push พร้อม Number Matching/polling หรือกรอกรหัส TOTP 6 หลักเพื่อตรวจผ่าน REST API มีปุ่มดู Source code จริง แสดง request/response ที่ปกปิดรหัส และดาวน์โหลดผล JSON ไม่เพิ่ม dependency และไม่ต้อง build image ใหม่
